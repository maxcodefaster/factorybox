# Factorybox v0.1.0-rc.1

This is the first release candidate for the standalone Factorybox runtime.
It provides system-container start, checkpoint, fork, pause, resume and recovery,
plus the Open Software Factory consumer integration and a small prepared pool.
IDEs and Dev Containers consume the runtime without owning its lifecycle.

The candidate targets Linux AMD64 with the currently admitted native host
profile, cgroup v2, 4096-byte pages and local persistent storage. Kernel admission
remains exact. This is not qualification for arbitrary Kubernetes nodes or cloud
providers. Use separate workers for different customers or trust domains.
Same-worker recovery does not establish cross-node migration or recovery after
worker replacement beyond the explicitly tested recovery lanes.

The original candidate scope was AMD64. The current release pipeline supports
both AMD64 and ARM64 and requires native gates on each before creating the
combined image manifest. The declared Systemd proc fixture retains the original
denial assertions when kcore exists and requires guest absence when the kernel
lacks it. This fixes a kernel-config assumption; it does not retroactively
qualify this older candidate or grant ARM64 production readiness. See the
[current readiness checklist](../first-release-status.md).

Original Factorybox code uses Apache-2.0. Sysbox and CRIU retain their original
terms. Distribution includes the exact component source archive and provenance;
see [LICENSING.md](../../LICENSING.md).

The release gate checks the delivered image version and license, CRIU core,
Sysbox unit and integration tests, lifecycle and systemd Bats tests, all fourteen
worker suites, planned and abrupt worker replacement and both Factory consumer
lanes. Failed or unrun required gates block this candidate's qualification.
The native gate receipt identifies the exact image and package.

The 24-hour endurance run, larger repeated-run series, broader host qualification
and further performance work follow this candidate. Existing timing results
describe older exact packages and do not promise this candidate's latency or p95.

## Upstream maintenance

Keep Sysbox and CRIU pinned. Review upstream changes monthly and before a
release, prioritizing security fixes and changes to namespaces, cgroups, mounts
and checkpoint/restore. Record the reviewed commits and the decision to adopt or
defer. Updating a pin requires the relevant regression and native gates.

Submit small, generally useful fixes separately, with a minimal reproduction,
the regression test, original attribution and the upstream contribution process.
Factorybox-specific orchestration stays here. AI-assisted authorship does not
replace review or tests and is not by itself a reason to rewrite working code.
No upstream submission is part of publishing this candidate.
